No radioactive spider here. My origin story is a terminal window and a lab that would not work until it did.

I'm a **Computer Science student at the Lyceum of the Philippines University – Manila** (Class of 2027) and an **AI Security Intern at RivanAI**. Most of my recent work happens in security labs: catching attacks with Wazuh, automating the response with Shuffle, watching Cisco gear with Zabbix, and pulling evidence out of memory with Volatility. When I'm not in a lab, I build web apps people can use, like NursePrep.

What I care about: systems that hold up when something goes wrong, documentation the next person can follow, and getting a little better every day.

<td width="50%" valign="top">

<sub>MISSION 01 · LOG ANALYSIS</sub>
#### [CyberSentinel](https://github.com/navinskyy/CyberSentinel)
**Problem:** Making sense of Windows Event Logs and other log exports without shipping them to a third-party service.<br/>
**Solution:** An offline, read-only, rule-based detection engine. Parsers feed normalized events to the rules, and findings land in a Streamlit dashboard with exportable reports.<br/>
**Tech:** `Python` `Streamlit` `.evtx / CSV / text logs`

</td>
<td width="50%" valign="top">

<sub>MISSION 02 · SECURITY AUTOMATION</sub>
#### [Wazuh × Shuffle SOAR](https://github.com/navinskyy/wazuh-shuffle)
**Problem:** SIEM alerts nobody sees in time.<br/>
**Solution:** An automated pipeline. Wazuh detects the attack, a Shuffle workflow picks it up from a webhook, and the alert lands on AlertBoard, a custom Python dashboard. Tested with a live brute-force attack.<br/>
**Tech:** `Wazuh 4.12` `Shuffle` `Rocky Linux 9.5` `Docker Compose` `Python`

</td>
</tr>
<tr>
<td width="50%" valign="top">

<sub>MISSION 03 · NETWORK MONITORING</sub>
#### [Network Monitoring Lab](https://github.com/navinskyy/linux-zabbix-core-switches-setup)
**Problem:** Watching Cisco network devices from a Linux workstation.<br/>
**Solution:** A Linux Mint PC becomes a Dockerized Zabbix server. It sits behind two Cisco core switches on a dedicated VLAN and uses static routes and SNMP to monitor a CSR1000v router.<br/>
**Tech:** `Linux Mint` `Docker` `Zabbix 7.0` `PostgreSQL 15` `Cisco IOS` `SNMP`

</td>
<td width="50%" valign="top">

<sub>MISSION 04 · DIGITAL FORENSICS</sub>
#### [Memory Forensics with Volatility 3](https://github.com/navinskyy/volatility)
**Problem:** RAM holds the evidence of what was running, and it disappears at power-off.<br/>
**Solution:** A hands-on lab journal: capture a memory dump, then investigate processes, network connections and artifacts with Volatility 3 plugins. Written for beginners.<br/>
**Tech:** `Volatility 3` `Python` `Windows`

</td>
</tr>
<tr>
<td width="50%" valign="top">

<sub>MISSION 05 · WEB PLATFORM</sub>
#### [NursePrep](https://github.com/navinskyy/NursePrep)
**Problem:** Filipino nursing graduates juggle scattered material while reviewing for the licensure exam (PNLE).<br/>
**Solution:** A single study platform with adaptive timed quizzes, spaced-repetition flashcards, analytics, and optional AI-assisted explanations. Progress syncs across devices. [Live site →](https://nurse-prep-pi.vercel.app)<br/>
**Tech:** `JavaScript` `Vite` `Firebase Auth` `Firestore`

</td>

**Solution:** Fully static, pre-rendered pages. The only client-side JavaScript is for the interactive parts: a typing race, dialogs, theme switching and keyboard shortcuts. [Live site →](https://navinskyy.vercel.app)<br/>
